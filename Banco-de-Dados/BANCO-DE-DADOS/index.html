Tópico 1

Modelo Relacional

Pense nisso como tabelas parecidas com planilhas do Excel que se conversam entre si por meio de códigos (IDs).

1. Como os dados se organizam (e as palavras que o professor cobra)

1

O que é

É o jeito de guardar informações usando tabelas com linhas e colunas, onde uma tabela se conecta com a outra.

2

Para que serve

Serve para não virar bagunça. Em vez de salvar tudo num arquivo de texto solto, você organiza clientes numa tabela, cidades em outra e vendas em outra.

3

Como funciona (Tradução dos nomes difíceis)

O professor usa nomes técnicos para coisas simples que você já conhece:

No dia a dia: Tabela Relação A tabela inteira (exemplo: a tabela de CLIENTES).
No dia a dia: Linha do Excel Tupla Cada linha cadastrada (exemplo: a linha com os dados do Carlos).
No dia a dia: Coluna Atributo O nome do campo (exemplo: Nome, Telefone, Endereço).
No dia a dia: Tipo da coluna Domínio O que pode entrar naquele campo (só número, só texto, data, etc.).
4

Exemplo simples

Pense numa planilha chamada CIDADE. Ela tem as colunas ID, NOME e UF. Se tiver 3 cidades cadastradas lá dentro, ela tem 3 tuplas (3 linhas) e 3 atributos (3 colunas).

5

Caso prático da vida real

No sistema de um mercado: você tem a tabela de PRODUTOS. Cada produto novo que chega na prateleira vira uma linha nova (uma tupla) com seu preço e código de barras.

6

O que preciso lembrar para a prova

Se o professor perguntar: Linha = Tupla, Coluna = Atributo e Tabela = Relação. Ele adora trocar a palavra "linha" por "tupla" nas perguntas!

2. Chave Primária (PK), Chave Estrangeira (FK) e Integridade

1

O que é

Chave Primária (PK): É o "CPF" ou "RG" de cada linha da tabela. É o número que não se repete nunca e garante que aquela linha seja única.
Chave Estrangeira (FK): É um campo que você coloca na tabela para "apontar" para outra tabela (é a ponte de ligação).
Integridade Referencial: É a regra que não deixa ninguém criar links quebrados no banco.

2

Para que serve

Serve para o banco não se perder. Sem a Chave Primária, você não saberia diferenciar dois clientes chamados "João da Silva". Sem a Chave Estrangeira, você não saberia qual cliente fez qual compra.

3

Como funciona

  • Duas regras da Chave Primária (PK):
    1. Não pode ter valor repetido.
    2. Não pode ficar em branco (nunca nula).
  • Como funciona a Chave Estrangeira (FK): Na tabela de Clientes, em vez de escrever o nome da cidade por extenso, você só anota o CIDADE_ID. O banco vai lá na tabela de Cidades e sabe exatamente qual cidade é.
  • E se eu tentar apagar uma cidade que tem clientes?
    • Modo padrão (RESTRICT): O banco proíbe e dá erro na hora. Ele diz: "Ei, não vou apagar Maringá porque ainda tem cliente morando lá!".
    • Modo cascata (CASCADE): O banco apaga a cidade e, junto com ela, deleta todos os clientes que estavam nela.
4

Exemplo simples

-- Tabela CIDADE: quem manda (tem a PK) ID: 1 | NOME: 'Maringá' | UF: 'PR'

-- Tabela CLIENTE: aponta pra cidade usando a FK ID: 10 | NOME: 'Helena' | CIDADE_ID: 1 <-- Esse "1" é a FK!
5

Caso prático da vida real (O problema dos "dados órfãos")

Imagine uma loja. Se alguém pudesse apagar o cliente "Carlos", mas as compras dele ficassem salvas no sistema, as notas fiscais ficariam sem dono ("órfãs"). Ninguém saberia quem comprou aquilo! A integridade referencial serve exatamente para proibir isso.

6

O que preciso lembrar para a prova

• A Chave Primária nunca pode ser nula e nunca se repete.
• A Chave Estrangeira só pode guardar um código que já existe na outra tabela.
• Integridade referencial é o que impede que existam registros órfãos (filhos sem pai).

Tópico 2

Cardinalidade (Quem se liga com quem)

É só descobrir a proporção das coisas: se uma coisa tem muitos da outra, ou se é muitos para muitos.

1. Relacionamento 1 : N (Um para Muitos)

1

O que é

É quando um lado da relação pode ter várias coisas do outro lado, mas o outro lado só pode ter uma.

2

Para que serve

É o tipo mais comum do mundo real. Serve para ligar coisas sem precisar repetir dados à toa.

3

Como funciona (A regrinha de ouro que sempre cai na prova)

⚠️ REGRA DE OURO: Em qual tabela você coloca a Chave Estrangeira (o ID do outro)?
SEMPRE NO LADO "MUITOS" (N)!

Pensa comigo: 1 Cidade tem MUITOS clientes. Mas cada cliente mora em 1 cidade.
Onde você coloca o código da cidade? No cadastro do CLIENTE!
Se você tentasse colocar o código do cliente dentro da Cidade, como faria quando a cidade tivesse 10.000 clientes? Teria que criar 10.000 colunas de cliente na mesma linha da cidade! Não faz sentido nenhum.

4

Exemplo simples

• 1 Fornecedor fornece para Muitas Compras.
• Quem é o lado "muitos"? A COMPRA.
• Então o campo FORNECEDOR_ID fica dentro da tabela COMPRA.

5

Caso prático da vida real

Na escola ou faculdade: 1 Turma tem muitos Alunos. Na ficha de matrícula do aluno é que vem escrito o código da turma dele, e não o contrário.

6

O que preciso lembrar para a prova

Se o professor perguntar: "O cliente nasce em uma cidade, mas a cidade tem muitos clientes. Onde fica a FK?"
Resposta direta: Na tabela CLIENTE, porque a FK sempre vai para o lado "Muitos" (N)!

2. Relacionamento N : N (Muitos para Muitos) e a Tabela do Meio

1

O que é

É quando os dois lados podem ter vários do outro. Exemplo: Uma Venda pode ter vários Produtos diferentes, e um mesmo Produto pode ser vendido em várias Vendas diferentes.

2

Para que serve (O problema do N:N)

Bancos de dados não conseguem ligar N:N direto. Não dá pra colocar a chave de um no outro. Para resolver isso, somos obrigados a criar uma tabelinha no meio, chamada de Tabela Associativa (ou intermediária).

3

Como funciona a tabela do meio

A tabela do meio (como VENDA_ITENS) pega o ID da Venda e o ID do Produto:

  • Ela junta os dois IDs para criar uma Chave Primária Composta (chave dupla).
  • Guarda também o que aconteceu na hora: quantos itens foram levados (QT) e quanto custou cada um (VL_UNIT).
4

Exemplo simples

Veja a tabelinha VENDA_ITENS na prática:

VENDA_ID (Código da Venda) PRODUTO_ID (Código do Produto) QT (Quantidade) VL_UNIT (Preço)
501 10 (Martelo) 2 R$ 20,00
501 11 (Prego) 50 R$ 0,20
5

Caso prático da vida real (A pegadinha clássica do professor!)

Cenário da lista de exercícios:
Na Venda 501, o cliente já comprou o Produto 10 (Martelo). Se ele resolver levar mais 5 martelos na mesma venda, o caixa pode tentar cadastrar uma linha nova com (501, 10)?
Resposta: NÃO PODE! Porque o par 501 e 10 é a Chave Primária. Se tentar inserir de novo, o banco dá erro de duplicação. O sistema tem que atualizar (dar UPDATE) na linha que já existe, mudando a quantidade de 2 para 7!

6

O que preciso lembrar para a prova

• Relacionamento N:N sempre gera uma tabela associativa (tabela intermediária).
• Na tabela associativa, as duas FKs juntas viram uma Chave Primária Composta.

Tópico 3

Normalização (Organizar as gavetas)

Pense na normalização como arrumar um guarda-roupa bagunçado em gavetas separadas para não perder nada.

1. Por que normalizar? As 3 dores de cabeça (Anomalias)

Se você colocar tudo misturado numa tabela só (tipo um tabelão gigante do Excel), você vai ter 3 problemas:

Anomalia de Inserção Você quer cadastrar um produto novo na loja, mas o sistema não deixa porque ninguém comprou ele ainda. Você fica travado.
Anomalia de Atualização O cliente mudou de telefone. Como o telefone dele estava copiado em 50 compras antigas, você atualiza em uma e esquece nas outras. Os dados ficam bagunçados.
Anomalia de Exclusão Você cancela uma venda e, sem querer, o sistema apaga o cliente do banco porque ele só existia naquela linha daquela venda.

2. Primeira Forma Normal (1FN) - Cada coisa no seu quadrado

1

O que é

Significa que cada campo só pode ter um único valor (tem que ser "atômico", ou seja, indivisível). Nada de listas ou múltiplos valores amontoados na mesma caixinha.

2

Para que serve

Para você conseguir pesquisar e filtrar. Se tiver dois telefones na mesma coluna, como o sistema busca quem tem o DDD 44?

3

Como funciona

  • ❌ Errado (Quebra a 1FN): Colocar na coluna Telefone: "9999-1111, 8888-2222".
  • ❌ Também errado: Fazer colunas repetidas: Telefone1, Telefone2, Telefone3.
  • ✔️ Certo (1FN): Cada linha tem apenas um telefone, ou cria-se uma tabelinha separada para telefones.
4

Exemplo simples

O campo ENDERECO: "Av Brasil, 1500, Maringá, PR". Para estar 100% na 1FN, quebre em colunas separadas: Rua, Número, Cidade e Estado.

6

O que preciso lembrar para a prova

Se a questão da prova mostrar: "O campo Telefone guarda vários números separados por vírgula. Qual forma normal foi violada?"
Resposta na lata: 1FN (Primeira Forma Normal)! A palavra-chave é ATOMICIDADE.

3. Segunda Forma Normal (2FN) - Não misture o produto com a venda

1

O que é

A tabela já tem que estar na 1FN. A regra é: todos os campos têm que depender da chave inteira, e não só de metade dela.

2

Para que serve

Evita repetir dados de produtos toda vez que uma venda é feita.

3

Como funciona (O segredo da 2FN)

💡 Preste muita atenção nisso:
Se a tabela tiver uma chave simples (só o ID), e já estiver na 1FN, ela já está automaticamente na 2FN!
A 2FN só dá problema quando a tabela tem chave composta (tipo VENDA_ITENS, que junta Venda_ID + Produto_ID).

Pense assim: na tabela VENDA_ITENS, o campo DESCRICAO_DO_PRODUTO depende da venda? Não! O Martelo continua sendo Martelo em qualquer venda. A descrição depende só do Produto, e não da Venda. Por isso, a descrição não pode ficar aí!

4

Exemplo simples

Tire a DESCRICAO_DO_PRODUTO de VENDA_ITENS e deixe-a guardada apenas na tabela PRODUTO. Em VENDA_ITENS fica só a QUANTIDADE vendida.

6

O que preciso lembrar para a prova

Se cair na prova: "Na tabela VENDA_ITENS (Venda_ID, Produto_ID), colocamos a coluna Nome_Produto. Qual regra foi violada?"
Resposta: Violou a 2FN, porque o nome do produto depende só de parte da chave (depende só do Produto_ID).

4. Terceira Forma Normal (3FN) - Não misture a Cidade com o Cliente

1

O que é

A tabela já tem que estar na 2FN. A regra é: um campo comum não pode depender de outro campo comum. Todo mundo tem que depender direto da Chave Primária.

2

Para que serve

Serve para não ficar repetindo informações que deveriam ter sua própria tabela.

3

Como funciona

Imagine a tabela: CLIENTE (ID, NOME, CIDADE_ID, NOME_CIDADE, UF).

  • O NOME depende do cliente (Beleza!).
  • Mas NOME_CIDADE e UF dependem do cliente? Não! Dependem do CIDADE_ID!
  • Maringá não é do Paraná por causa do cliente João; ela é do Paraná por conta da própria cidade. Isso é o que chamamos de dependência transitiva.
4

Exemplo simples (Como consertar)

Tire NOME_CIDADE e UF da tabela de Clientes e crie uma tabela própria chamada CIDADE. No Cliente você só deixa o CIDADE_ID.

6

O que preciso lembrar para a prova

A 3FN é o motivo de separarmos Cidade de Cliente! Se o campo não depende do ID do cliente, ele tem que ir pra tabela dele.

Tópico 4

Create Table (Criando as tabelas no código)

É a receita de bolo em SQL para mandar o computador criar as tabelas com os tipos certos.

1. Os tipos de dados que o professor usa

INT Para números inteiros, sem vírgula (ex: códigos de ID, quantidades).
VARCHAR(100) Para textos com tamanho que varia até 100 letras (ex: Nomes, Ruas).
CHAR(2) Para texto de tamanho exato e fixo (ex: Estado tem sempre 2 letras: 'PR', 'SP').
DECIMAL(10,2) Para dinheiro e preços (guarda números com 2 casas decimais depois da vírgula).
DATE Para datas (formato ano-mês-dia: '2026-09-19').
PRIMARY KEY Avisa o banco que aquele campo é a Chave Primária.
FOREIGN KEY Avisa o banco que aquele campo é a Chave Estrangeira ligada em outra tabela.

2. Como escrever os 3 tipos de tabelas que caem na prova

A

Tipo 1: Tabela Simples (ex: CIDADE)

Essa não depende de ninguém, então é a primeira a ser criada:

CREATE TABLE CIDADE(
    ID INT PRIMARY KEY,
    NOME VARCHAR(100),
    UF CHAR(2)
);
B

Tipo 2: Tabela com Ligação/FK (ex: CLIENTE)

Tem o campo CIDADE_ID que aponta para o ID de CIDADE:

CREATE TABLE CLIENTE(
    ID INT NOT NULL PRIMARY KEY,
    CIDADE_ID INT NOT NULL,
    NOME VARCHAR(100),
    ENDERECO VARCHAR(150),
    FONE VARCHAR(20),
    DATA_NASC DATE,
    FOREIGN KEY(CIDADE_ID) REFERENCES CIDADE(ID)
);
C

Tipo 3: Tabela do Meio N:N com Chave Dupla (ex: VENDA_ITENS)

Junta os dois IDs para criar a Chave Primária Composta:

CREATE TABLE VENDA_ITENS(
    PRODUTO_ID INT NOT NULL,
    VENDA_ID INT NOT NULL,
    VL_UNIT DECIMAL(10,2),
    QT INT NOT NULL,
    VL_TOTAL DECIMAL(10,2),
    PRIMARY KEY (PRODUTO_ID, VENDA_ID),
    FOREIGN KEY (VENDA_ID) REFERENCES VENDA(ID),
    FOREIGN KEY (PRODUTO_ID) REFERENCES PRODUTO(ID)
);
6

O que preciso lembrar para a prova

1. A ordem importa: Você não pode criar a tabela CLIENTE antes de criar a tabela CIDADE, porque o cliente precisa apontar para uma cidade que já existe!
2. Chave dupla: Se escreve no final: PRIMARY KEY (campo1, campo2).
3. Chave estrangeira: A regrinha é sempre FOREIGN KEY (campo_daqui) REFERENCES tabela_de_la(campo_de_la).
